# Лабораторная работа № 1: Telegram-бот — ассистент для задач

Бот принимает задачи с названием и необязательным описанием, сортирует их по трём
приоритетам, хранит список дел и отправляет напоминания. Команда `/add` запускает
пошаговое создание с кнопками. Интерфейс на русском языке, работа — в личном чате.
Внешняя LLM и платные AI API для работы бота не нужны.

## Файлы проекта

- `bot.py` — команды, работа с SQLite, отправка напоминаний.
- `requirements.txt` — зафиксированные версии прямых зависимостей.
- `.env.example` — образец настроек без токена.
- `.gitignore` — исключения для секретов, базы, окружения и служебных файлов.
- `prompts/v001.md` — исходный промпт реализации.
- `prompts/v002.md` — актуальный промпт с описаниями, диалогом и новыми командами.
- `prompts/README.md` — правила сохранения следующих версий промпта.
- `AGENTS.md` — инструкции для дальнейшей работы и сохранения версий промпта.
- `tests/test_bot.py` — автоматические проверки без подключения к Telegram.
- `lab1_report.md` — отчёт по лабораторной работе.
- `report_assets/screenshots/` — папка для скриншотов отчёта.
- `data/tasks.sqlite3` — база, которая создаётся автоматически при запуске.

## Короткий алгоритм создания бота

1. Зарегистрировать бота через [@BotFather](https://t.me/BotFather) командой `/newbot`
   и получить токен.
2. Сформулировать требования в промпте для LLM, получить файлы проекта и проверить код.
3. Заполнить `.env`, запустить тесты и затем `bot.py`.

## Версия Python и зависимости

Проект проверен на Python **3.14.7**. Основные зависимости: `python-telegram-bot 22.8`
с JobQueue, `python-dotenv 1.2.3`, `tzdata 2026.4`; для хранения используется SQLite
из стандартной библиотеки Python. Полный список зафиксирован в `requirements.txt`.

## Файл `.env`

Создайте `.env` по образцу `.env.example` и укажите настройки:

```dotenv
TELEGRAM_BOT_TOKEN=
TIMEZONE=Europe/Moscow
DATABASE_PATH=data/tasks.sqlite3
```

Токен получают у BotFather; его нельзя добавлять в Git или показывать в отчёте.
По умолчанию используется часовой пояс `Europe/Moscow`, база создаётся по пути
`lab1/data/tasks.sqlite3`.

## Запуск и остановка

Из папки `lab1` на macOS/Linux:

```bash
.venv/bin/python bot.py
```

На Windows:

```powershell
.\.venv\Scripts\python.exe bot.py
```

## Команды

| Действие | Сообщение |
| --- | --- |
| Приветствие | `/start` |
| Помощь | `/help` |
| Пошагово добавить задачу с описанием | `/add` |
| Быстро добавить задачу без описания | `Купить продукты` или `/add Купить продукты` |
| Активные задачи | `/list` |
| Все задачи | `/list_all` |
| Изменить приоритет | `/priority <id> высокий` |
| Выполнить задачу | `/done <id>` |
| Удалить задачу | `/delete <id>` |
| Установить/заменить напоминание | `/remind <id> 15.10 18:30` |
| Отменить напоминание | `/remind_off <id>` |
| Отменить пошаговое создание | `/cancel` |

Заменяйте `<id>` на ID своей задачи (без угловых скобок), а дату — на будущую.
Приоритеты: 🔴 `высокий`, 🟡 `средний` (по умолчанию), 🟢 `низкий`.
Внутри одного приоритета задачи идут в порядке добавления. ID общие для базы,
поэтому у пользователя могут встречаться пропуски в нумерации.

Суммарный размер названия и описания — до 3000 символов в UTF-16 (большинство эмодзи
занимают два). Описание показывается в списках и напоминаниях, если оно заполнено.
Дата принимается в формате `ДД.ММ ЧЧ:ММ` и относится к текущему году в `TIMEZONE`.
Прошедшая дата вызывает ошибку; бот не переносит её на следующий год автоматически.
Можно также указать год явно: `/remind <id> 15.10.2027 18:30`.
Распознавание фраз вроде «завтра вечером» не предусмотрено.
Редактирование уже отправленного сообщения не меняет задачу.
Длинные списки автоматически делятся на сообщения.

## Пошаговое добавление

1. Отправьте `/add`: бот ответит «Введите название задачи».
2. Введите название: бот предложит «Введите описание».
   Введите описание или нажмите «Пропустить».
3. Бот предложит «Укажите приоритет (высокий, средний, низкий)».
   Выберите одну из трёх кнопок или введите вариант текстом.
4. Бот предложит «Установить напоминание» с форматом `ДД.ММ ЧЧ:ММ`, текущим годом
   и часовым поясом. Введите будущие дату и время или нажмите «Пропустить».
5. Задача сохранится, бот покажет все её данные и уберёт временную клавиатуру.

При неверном вводе бот просит повторить текущий шаг, сохраняя предыдущие ответы.
Чтобы отменить создание, отправьте `/cancel`; чтобы начать заново — `/add`.
`/start` также сбрасывает незавершённый диалог. `/help`, `/list` и `/list_all`
доступны во время создания и не сбрасывают ответы.

Черновик сохраняется в памяти отдельно для каждого пользователя. Пока диалог открыт,
обычный текст считается ответом на текущий шаг. В базу задача записывается одной
операцией в конце диалога. После перезапуска незавершённое создание нужно начать
заново через `/add`; уже сохранённые задачи остаются в базе.

## Хранение и напоминания

SQLite хранит ID задачи, ID владельца и чата, название, описание, приоритет, статус выполнения,
дату создания, время напоминания, состояние доставки, следующую попытку и время отправки.
Команды проверяют владельца: другой пользователь не может прочитать или изменить задачу,
даже зная её ID. В группах бот предлагает перейти в личный чат.

Старая база совместима с новой версией: при запуске автоматически добавляется поле
`description` с пустым значением для существующих задач. Их ID, текст, приоритеты,
статусы и напоминания сохраняются. Повторный запуск миграции безопасен.

JobQueue проверяет базу каждые 10 секунд; обычная задержка составляет до 10 секунд
плюс время запроса к Telegram. После запуска первая проверка происходит примерно
через секунду. Пропущенные во время остановки напоминания отправляются с отметкой
о задержке. Уже доставленные не отправляются заново при обычном перезапуске.

На задачу приходится одно напоминание. Новая дата заменяет прежнюю; `/done`,
`/delete` и `/remind_off <id>` отменяют доставку. При временной ошибке сети бот повторяет
попытку через минуту; при ограничении частоты учитывает время ожидания Telegram.
При блокировке бота или недоступном чате список показывает «не доставлено».
После восстановления доступа установите напоминание заново.

SQLite и Telegram не поддерживают общую транзакцию: если процесс аварийно завершится
после отправки сообщения, но до записи результата в базу, возможен повтор.
Такая же неопределённость возможна при потере ответа Telegram после принятия сообщения.

Для резервной копии остановите бота и скопируйте файл базы в безопасное место.
Удаление базы удалит все задачи. База и `.env` исключены из Git.

## Проверки

Автоматические проверки из папки `lab1`:

```bash
python -m unittest discover -s tests -v
python -m pip check
```

На Windows замените `python` на `.\.venv\Scripts\python.exe`.
Тесты создают временную базу, подменяют доставку сообщений и не требуют токена.
Проверяются команды, описание, весь пошаговый диалог и его кнопки, пропуски, отмена,
повтор после ошибки SQLite, независимость диалогов пользователей, миграция старой базы,
короткие даты и високосные годы, сохранение после перезапуска, отмена и замена напоминаний,
повтор после сетевой ошибки, блокировка доставки, ограничения длины, скрытие токена
в логах и работа настоящего диспетчера Telegram и JobQueue с локальной подменой API.

Ручная проверка с настоящим ботом:

1. Отправьте `/start`, затем `/add`. Введите название и описание, выберите приоритет
   кнопкой, укажите будущую дату в формате `ДД.ММ ЧЧ:ММ`. Запишите выданный ID.
2. Создайте ещё две задачи, пропустив описание и напоминание. Проверьте `/list`,
   сортировку и отображение описания. Проверьте быстрые способы: текст и `/add Название`.
3. Назначьте напоминание на 1–2 минуты вперёд в часовом поясе из ответа.
   Дождитесь сообщения и проверьте, что оно содержит нужный текст и ID.
4. Назначьте новое напоминание, замените время, затем отмените через `/remind_off <id>`.
   Убедитесь, что сообщение не приходит. Повторите отмену через `/done` и `/delete`.
5. Проверьте, что выполненная задача видна в `/list_all`, но отсутствует в `/list`.
6. Назначьте напоминание на ближайшее время. Остановите бота, дождитесь этого времени
   и запустите снова: должно прийти одно сообщение с отметкой о задержке.
   Перезапустите ещё раз: доставленное напоминание не должно повториться.
7. Откройте бота со второго Telegram-аккаунта. Его список должен быть отдельным.
   Попытки изменить, выполнить, удалить задачу первого аккаунта или назначить ей
   напоминание должны вернуть «Задача не найдена».
8. Отправьте неверную дату, дату в прошлом, `/done abc`, неизвестную команду,
   фотографию и голосовое сообщение. Бот должен показать понятные подсказки.
9. В группе отправьте команду, адресованную боту: он должен предложить личный чат.
10. В диалоге `/add` введите неверный приоритет и неверную дату: шаг должен сохраниться.
    Проверьте `/help` и `/list_all` посреди диалога, затем `/cancel`: задача не создаётся.
    Повторите `/add` с двумя аккаунтами одновременно и проверьте независимость ответов.

Доставка настоящих сообщений, доступность токена и взаимодействие с двумя реальными
Telegram-аккаунтами требуют ручной проверки. Автоматические тесты её не заменяют.

Результат локальной проверки 01.10.2026: **36 тестов прошли** на Python 3.14.7;
`pip check` не обнаружил конфликтов зависимостей. Настоящий токен не использовался,
запуск и доставка сообщений в Telegram пока не проверены.

## Если что-то не работает

- `No module named telegram` — установите зависимости тем же Python, которым запускаете бота.
- Сообщение о `TELEGRAM_BOT_TOKEN` — заполните `.env` в папке `lab1`.
- Токен отклонён — проверьте его в BotFather, скопируйте заново без лишних символов.
- `Conflict` — остановите вторую копию бота с тем же токеном.
- Ошибка `TIMEZONE` — используйте название вроде `Europe/Moscow`.
- Ошибка SQLite — проверьте путь и права на папку базы, свободное место и логи терминала.
- Нет ответа — проверьте работающий терминал, интернет, правильного бота и `/start`.
- Задача могла сохраниться, даже если ответ потерялся из-за сети: перед повтором
  добавления проверьте `/list_all`.
