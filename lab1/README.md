# Telegram-бот — ассистент для задач (лабораторные № 1–3)

Бот принимает задачи с названием и необязательным описанием, сортирует их по трём
приоритетам, хранит список дел и отправляет напоминания. Поддерживает поиск по части
названия или описания, редактирование, личные группы, сроки и фильтры задач.
Основное управление — кнопками под сообщениями: меню, списки и карточки.
Текст нужен для свободных полей; команды остаются альтернативой.
Интерфейс на русском языке, работа — в личном чате.
Внешняя LLM и платные AI API для работы бота не нужны.

## Короткий алгоритм создания бота

1. Зарегистрировать бота через [@BotFather](https://t.me/BotFather) командой `/newbot`
   и получить токен.
2. Сформулировать требования в промпте для LLM, получить файлы проекта и проверить код.
3. Заполнить `.env`, запустить тесты и затем `bot.py`.

## Версия Python и зависимости

Проект проверен на Python **3.14.7**. Основные зависимости: `python-telegram-bot 22.8`
с JobQueue, `python-dotenv 1.2.3`, `tzdata 2026.4`; для хранения используется SQLite
из стандартной библиотеки Python. Полный список зафиксирован в `requirements.txt`.

## Файл `.env`

Создайте `.env` по образцу `.env.example` и укажите настройки:

```dotenv
TELEGRAM_BOT_TOKEN=
TIMEZONE=Europe/Moscow
DATABASE_PATH=data/tasks.sqlite3
```

Токен получают у BotFather; его нельзя добавлять в Git или показывать в отчёте.
По умолчанию используется часовой пояс `Europe/Moscow`, база создаётся по пути
`lab1/data/tasks.sqlite3`.

## Управление

Подготовка к Railway описана в [lab3/README.md](../lab3/README.md).
Локальный запуск и `.env` остались прежними. Эта доработка не выполняет push или
деплой; статус облачной версии нужно проверять отдельно.

Отправьте `/start`: бот уберёт клавиатуру старой версии и покажет главное меню.
Доступны «Добавить задачу», «Мои задачи», «Поиск», «Группы» и «Помощь».
Списки и группы показываются по 5 элементов; кнопка задачи открывает полную карточку.
Из неё можно выполнить, изменить, перенести в группу, настроить срок и напоминание,
удалить задачу или вернуться к списку. ID для кнопочного управления не нужен.

Обычный текст **вне формы не создаёт задачу**. Начните с кнопки «Добавить задачу»
или `/add`; для явного быстрого добавления есть `/add Название`.

Команды как альтернативный способ управления:

| Действие | Сообщение |
| --- | --- |
| Приветствие | `/start` |
| Главное меню | `/menu` |
| Помощь | `/help` |
| Пошагово добавить задачу с описанием | `/add` |
| Быстро добавить задачу без описания | `/add Купить продукты` |
| Активные задачи | `/list` |
| Все задачи | `/list_all` |
| Найти по части названия или описания | `/search <текст>` |
| Пошагово изменить название и описание | `/edit <id>` |
| Создать группу (бот запросит название) | `/group_create` |
| Группы и количество активных задач | `/groups` |
| Все задачи группы | `/group_tasks <group_id>` |
| Переименовать группу | `/group_rename <group_id>` |
| Удалить группу после подтверждения, сохранив задачи | `/group_delete <group_id>` |
| Выбрать или изменить группу задачи | `/task_group <id>` |
| Убрать задачу из группы | `/task_ungroup <id>` |
| Изменить приоритет | `/priority <id> высокий` |
| Выполнить задачу | `/done <id>` |
| Удалить задачу после подтверждения | `/delete <id>` |
| Установить/заменить напоминание | `/remind <id> 15.10 18:30` |
| Отменить напоминание | `/remind_off <id>` |
| Отменить текущий диалог | `/cancel` |

Заменяйте `<id>` на ID своей задачи, `<group_id>` — на ID своей группы
(без угловых скобок), а дату — на будущую.
Приоритеты: 🔴 `высокий`, 🟡 `средний` (по умолчанию), 🟢 `низкий`.
Внутри одного приоритета задачи идут в порядке добавления. ID общие для базы,
поэтому у пользователя могут встречаться пропуски в нумерации.

Суммарный размер названия и описания — до 3000 символов в UTF-16 (большинство эмодзи
занимают два). Описание показывается в карточках и напоминаниях, если оно заполнено.
Дата напоминания принимается в формате `ДД.ММ ЧЧ:ММ` и относится к текущему году
в `TIMEZONE`. Прошедшее напоминание вызывает ошибку; переноса на следующий год нет.
Можно также указать год явно: `/remind <id> 15.10.2027 18:30`.
Распознавание фраз вроде «завтра вечером» не предусмотрено.
Редактирование уже отправленного сообщения не меняет задачу.
Длинные ответы делятся на сообщения, списки — на страницы.

## Пошаговое добавление

1. Нажмите «Добавить задачу» или отправьте `/add`: бот ответит «Введите название задачи».
2. Введите название: бот предложит «Введите описание».
   Введите описание или нажмите «Пропустить».
3. Бот предложит «Укажите приоритет (высокий, средний, низкий)».
   Выберите одну из трёх кнопок.
4. Выберите группу кнопкой или нажмите «Пропустить». Все группы доступны постранично.
5. Выберите срок: сегодня, завтра, произвольная дата или дата с временем.
   «Пропустить» оставляет задачу без срока.
6. Выберите быстрое напоминание, введите будущую дату/время или нажмите «Пропустить».
   При подходящем сроке доступно предложение «За час до срока»; оно не включается само.
7. Проверьте итог, включая точное время напоминания, и нажмите «Сохранить».
   Только теперь задача записывается в SQLite.

При неверном вводе бот просит повторить текущий шаг, сохраняя предыдущие ответы.
Кнопка «Назад» возвращает на предыдущий шаг, сохраняя введённые поля.
«Отмена», «Меню», `/cancel`, `/start` и `/menu` сбрасывают незавершённый диалог.
Помощь и просмотр списков не сбрасывают черновик. Новый изменяющий диалог
заменяет прежний с уведомлением. Слова «Меню» и «Пропустить» можно вводить как
буквальные названия/описания: управляющими являются кнопки, а не эти слова.

Черновик сохраняется в памяти отдельно для каждого пользователя. Пока диалог открыт,
обычный текст считается ответом на текущий шаг. В базу задача записывается одной
операцией после подтверждения. Форма действует 30 минут, подтверждение удаления —
5 минут; кнопки изменяющих действий тоже ограничены по времени.
После перезапуска старые кнопки и черновики недействительны: откройте `/start`.
Уже сохранённые задачи остаются в базе.

## Поиск, редактирование и группы

`/search продук` находит «Купить продукты», а `/search отч` — «Подготовить отчёт».
Поиск работает по подстроке названия и описания, не учитывает регистр, включая
кириллицу, и включает выполненные задачи. В карточке результата видна дата создания.
Символы `%` и `_` считаются обычным текстом, а не шаблонами поиска.

`/edit <id>` последовательно предлагает новое название и описание. Кнопка «Оставить»
сохраняет соответствующее поле, «Очистить» удаляет описание. Изменения записываются
только после «Сохранить»; `/cancel` оставляет прежние данные. Приоритет, статус,
дата создания, группа и напоминание не меняются. Напоминание использует актуальные
название и описание.

Группы личные: одна задача принадлежит одной группе либо находится без группы.
Название группы — одна непустая строка до 80 символов UTF-16; повторяющиеся названия
у одного пользователя запрещены без учёта регистра. `/groups` показывает число
активных задач, `/group_tasks <group_id>` — все задачи выбранной группы.
`/task_group <id>` предлагает кнопки выбора; повторное назначение переносит задачу.
Все группы доступны кнопками по страницам. В карточке группы можно посмотреть
задачи, добавить новую или существующую, переименовать и удалить группу.
Удаление требует подтверждения и не удаляет задачи и их напоминания.

Пример: `/group_create` → `Учёба` → «Сохранить» → `/task_group <id>` →
кнопка нужной группы → «Сохранить» → `/group_tasks <group_id>`.
При пошаговом `/add` группу можно выбрать до напоминания;
быстрое добавление `/add Название` создаёт задачу без группы.
`/cancel` работает и при создании/переименовании группы, и при её назначении.

## Сроки, быстрые напоминания и фильтры

Срок выполнения и напоминание — независимые поля. Срок задаётся при создании или
кнопкой «Срок» в карточке: `ДД.ММ`/`ДД.ММ.ГГГГ`, при необходимости с `ЧЧ:ММ`.
Без времени задача просрочена после окончания выбранного дня в `TIMEZONE`,
с временем — начиная с указанного момента. Прошедший срок разрешён с предупреждением.
Смена срока не переносит напоминание; отмена напоминания не удаляет срок.
Выполнение сохраняет срок, но отменяет уведомление.

Для напоминания есть «Через 15 минут», «Через час», «Завтра в 09:00», ручная дата
и отключение. Если возможно, бот предлагает «За час до срока», показывая точную дату.
Для срока без времени это за час до окончания выбранного дня.
Напоминание включается только после выбора и сохранения. Уже прошедшее время
отклоняется, в том числе если оно прошло, пока пользователь просматривал итог.

В списках доступны фильтры: активные, выполненные, все, высокий приоритет,
с напоминаниями, на сегодня, просроченные. Последние четыре показывают только
активные задачи. «На сегодня» определяется сроком, а не датой уведомления;
«С напоминаниями» — ожидающие отправки, включая повторную попытку.
Фильтры работают и в выбранной группе. Возврат из карточки сохраняет поиск,
фильтр и страницу; после удаления страницы пересчитываются.

## Хранение и напоминания

Таблица `tasks` хранит ID задачи, ID владельца и чата, название, описание, приоритет,
статус выполнения, дату создания, параметры доставки напоминания и необязательный
`group_id`, отдельные `deadline_at` и `deadline_has_time`, версию записи `revision`.
Таблица `task_groups` хранит ID и владельца группы, название, его ключ
для проверки уникальности без учёта регистра и дату создания.
Команды проверяют владельца задачи и группы: другой пользователь не может прочитать
или изменить их, даже зная ID. В групповых чатах Telegram бот предлагает личный чат.
История сообщений и отдельные профили пользователей в базе не сохраняются.

Старая база совместима с новой версией: при запуске автоматически добавляется поле
`description`, если его ещё нет, и `group_id`, создаётся таблица `task_groups`.
При новой миграции добавляются также дедлайн и версии записей. Старым задачам
срок не назначается. Их ID, тексты, описания, приоритеты, статусы, группы и параметры
доставки сохраняются. Повторная миграция не сбрасывает имеющиеся данные.
Для даты без времени хранится начало следующего местного дня как UTC timestamp,
а показывается выбранная дата. Рабочую базу локальная разработка не изменяет;
миграция произойдёт при запуске новой версии с этой базой.

JobQueue проверяет базу каждые 10 секунд; обычная задержка составляет до 10 секунд
плюс время запроса к Telegram. После запуска первая проверка происходит примерно
через секунду. Пропущенные во время остановки напоминания отправляются с отметкой
о задержке. Уже доставленные не отправляются заново при обычном перезапуске.

На задачу приходится одно напоминание. Новая дата заменяет прежнюю; `/done`,
подтверждённое удаление и `/remind_off <id>` отменяют доставку. При временной ошибке сети бот повторяет
попытку через минуту; при ограничении частоты учитывает время ожидания Telegram.
При блокировке бота или недоступном чате карточка показывает «не доставлено».
После восстановления доступа установите напоминание заново.

SQLite и Telegram не поддерживают общую транзакцию: если процесс аварийно завершится
после отправки сообщения, но до записи результата в базу, возможен повтор.
Такая же неопределённость возможна при потере ответа Telegram после принятия сообщения.

Для резервной копии остановите бота и скопируйте файл базы в безопасное место.
Удаление базы удалит все задачи и группы. База и `.env` исключены из Git.

## Проверки

Автоматические проверки из папки `lab1`:

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
```

На Windows замените `.venv/bin/python` на `.\.venv\Scripts\python.exe`.
Тесты создают временную базу, подменяют доставку сообщений и не требуют токена.
Проверяются команды, описание, весь пошаговый диалог и его кнопки, пропуски, отмена,
повтор после ошибки SQLite, независимость диалогов пользователей, миграция старой базы,
короткие даты и високосные годы, сохранение после перезапуска, отмена и замена напоминаний,
повтор после сетевой ошибки, блокировка доставки, ограничения длины, скрытие токена
в логах и работа настоящего диспетчера Telegram и JobQueue с локальной подменой API.
Также проверяются поиск по фрагменту и кириллица, редактирование с отменой, операции
с группами, перенос задач, дубли названий, чужие ID и кнопки, атомарное удаление
группы при ошибке SQLite и актуальные данные в напоминаниях.
Новые проверки охватывают меню, страницы и карточки, подтверждение сохранения/удаления,
границы сроков и часовых поясов, быстрые напоминания, текст вне формы, чужие и устаревшие
кнопки, одновременные нажатия и защиту от дубликатов при ошибках чтения/отправки.

Ручная проверка с настоящим ботом:

1. Откройте `/start` и создайте задачу кнопками, включая описание, группу и срок.
   До «Сохранить» задачи не должно быть в списке. Проверьте «Назад» и «Отмена».
2. Откройте карточку: измените поля, найдите задачу по части названия/описания,
   переключите фильтры. Обычный текст после выхода в меню не должен создать задачу.
3. Установите ручное напоминание на несколько минут вперёд; проверьте доставку,
   кнопки в уведомлении, замену/отключение и независимость от срока.
4. Проверьте подтверждение удаления задачи/группы и отдельные списки другого аккаунта.

Доставка настоящих сообщений, доступность токена и взаимодействие с двумя реальными
Telegram-аккаунтами требуют ручной проверки. Автоматические тесты её не заменяют.
Подробные сценарии, повторный деплой и проверка сохранности после перезапуска:
[lab3/manual_checks.md](../lab3/manual_checks.md).

Результат локальной проверки 10.10.2026: **104 теста прошли** на Python 3.14.7;
`pip check` не обнаружил конфликтов зависимостей. Настоящий токен не использовался,

## Если что-то не работает

- `No module named telegram` — установите зависимости тем же Python, которым запускаете бота.
- Сообщение о `TELEGRAM_BOT_TOKEN` — заполните `.env` в папке `lab1`.
- Токен отклонён — проверьте его в BotFather, скопируйте заново без лишних символов.
- `Conflict` — остановите вторую копию бота с тем же токеном.
- Ошибка `TIMEZONE` — используйте название вроде `Europe/Moscow`.
- Ошибка SQLite — проверьте путь и права на папку базы, свободное место и логи терминала.
- Нет ответа — проверьте работающий терминал, интернет, правильного бота и `/start`.
- Задача могла сохраниться, даже если ответ потерялся из-за сети: перед повтором
  добавления проверьте `/list_all`.
- Кнопка устарела — откройте `/start` и актуальную карточку. Кнопки хранятся в памяти,
  ограничены по времени и не действуют после перезапуска.
