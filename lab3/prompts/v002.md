# Промпт лабораторной № 3: кнопочный интерфейс и дедлайны

На момент сохранения промпта требования согласованы, реализация ещё не начата.
Актуальный результат выполнения указан в `README.md` этой папки промптов.
Предыдущая версия `v001.md` остаётся неизменной. Это новая итерация по предложениям
ассистента и решениям пользователя, а не реализация полученных отзывов друзей.

Доработай существующего Telegram-бота — личного ассистента для задач — на Python 3.14
с текущими python-telegram-bot 22.8 (JobQueue), python-dotenv 1.2.3, tzdata 2026.4
и SQLite из стандартной библиотеки. Код, тесты, зависимости и сборочная конфигурация
остаются в lab1; материалы этой итерации — в lab3. Сохрани polling и подготовку Railway:
Root Directory /lab1, railpack.json с python -u bot.py, .python-version 3.14,
.dockerignore, токен из Variables, TIMEZONE и DATABASE_PATH внутри Volume /data.

Существующий функционал, который необходимо сохранить:
- Личные задачи: название, необязательное описание, высокий/средний/низкий приоритет,
  статус выполнения, группа, время создания, одно сохраняемое напоминание.
- Поиск по части названия/описания без учёта регистра, включая кириллицу.
- Редактирование названия/описания, смена приоритета, выполнение и удаление.
- Личные группы: создание, просмотр, переименование, удаление с сохранением задач,
  назначение, перенос и удаление задачи из группы.
- Команды /start, /help, /add, /list, /list_all, /search, /edit, /priority, /done,
  /delete, /remind, /remind_off, /cancel, /group_create, /groups, /group_tasks,
  /group_rename, /group_delete, /task_group, /task_ungroup.
- Владельцы проверяются при каждой операции. В групповых чатах бот предлагает личный чат.
- Напоминания переживают перезапуск, временные ошибки допускают повторную попытку,
  выполненные/удалённые задачи не получают уведомления, токен скрывается в логах.

Реализуй пять доработок:

1. Кнопки вместо обязательных команд и ID:
   - Главное меню: Добавить задачу, Мои задачи, Поиск, Группы, Помощь.
   - Inline-кнопки под сообщениями; слова из названий кнопок не являются командами
     при вводе пользовательского названия/описания.
   - Списки и результаты поиска/группы доступны постранично; выбор объекта кнопкой
     открывает полную карточку с действиями, возврат сохраняет контекст списка.
   - Все существующие операции доступны через кнопки. Текст требуется только для
     свободных значений: названия, описания, поиска и произвольной даты/времени.
   - В формах предусмотри Назад, Отмена, Пропустить/Оставить/Очистить где уместно.
     Создание: название → описание → приоритет → группа → срок → напоминание
     → итог → Сохранить. Запись выполняется только после подтверждения.
   - Команды оставить альтернативой. /add Название — явное быстрое добавление.
     Обычный текст вне активной формы задачу НЕ создаёт и не подставляется автоматически:
     показать подсказку и кнопки добавления/меню. Это согласованное изменение поведения.
   - К напоминанию прикрепить кнопки открытия и выполнения задачи.

2. Быстрые напоминания:
   - Через 15 минут, Через час, Завтра в 09:00, Ввести дату, Отключить/Пропустить.
   - При наличии дедлайна предложить За час до срока с точной датой, только если
     этот момент ещё в будущем. Без согласия пользователя ничего не устанавливать.
   - Дата/время рассчитываются в TIMEZONE и показываются перед подтверждением.
     Сохранение проверяет актуальность времени; замена не создаёт второе уведомление.

3. Безопасное удаление:
   - И кнопка, и /delete <id> сначала показывают актуальную задачу и одноразовое
     подтверждение Да, удалить / Отмена. Без подтверждения данные остаются.
   - Удаление группы также объясняет сохранение её задач и требует подтверждения.
   - Защитить подтверждения от повторов, чужих пользователей, истечения срока,
     смены диалога, перезапуска и изменения объекта после показа.

4. Фильтры списков:
   - Активные, Выполненные, Все, Высокий приоритет, С напоминаниями, На сегодня,
     Просроченные. В первой версии это отдельные готовые представления.
   - Приоритет/напоминания/сегодня/просроченные показывают только активные задачи.
     С напоминаниями — ожидающие отправки, в том числе повторной попытки.
   - Сегодня определяется дедлайном в местном календарном дне, не напоминанием;
     просроченные ранее сегодня также входят. Задачи без срока не входят в списки сроков.
   - Фильтр может действовать внутри выбранной группы; всегда проверять владельца.
     Сортировка остаётся приоритет → создание → ID. Страницы пересчитываются после изменений.

5. Отдельный дедлайн:
   - Необязательная дата с необязательным временем; отдельная настройка в карточке.
     Кнопки Сегодня, Завтра, Выбрать дату, Указать дату и время, Убрать срок/Пропустить.
   - Форматы ДД.ММ и ДД.ММ.ГГГГ, с временем ЧЧ:ММ; короткая дата — текущий год.
   - Без времени задача действует до конца выбранного дня, показывать дату без
     искусственно указанного времени; с временем просрочка наступает в этот момент.
   - Прошедший дедлайн разрешается с понятным предупреждением; напоминание в прошлом — нет.
   - Сохранять deadline_at отдельно от remind_at и флаг deadline_has_time.
     Для даты без времени хранить границу начала следующего местного дня, а при
     отображении/фильтрации использовать выбранный день. Хранение timestamps — UTC.
   - Напоминание за час до срока без времени — за час до окончания выбранного дня,
     показывать точный результат пользователю. Изменение срока не переносит напоминание
     автоматически, отмена напоминания не удаляет срок. Выполнение сохраняет срок.

Технические требования:
- Следуй подробным правилам lab3/improvements_plan.md; отдели хранение и бизнес-действия
  от экранов и обработки Telegram. Кнопки и команды используют общие проверки/транзакции.
- Добавь CallbackQueryHandler и callback_query в allowed_updates, отвечай на каждый
  callback, корректно обрабатывай недоступные сообщения и ошибки обновления интерфейса.
- Ограничивай данные кнопок 64 байтами и сообщения лимитами Telegram. Используй
  разрешённые коды действий и служебные ID, не пользовательский текст или SQL.
- Проверяй владельца и актуальность объекта/диалога при каждом нажатии, обеспечь защиту
  от повторной записи при двойном клике. Старые кнопки предлагают открыть новый экран.
- Черновики отдельные по пользователю/чату, запись атомарная; ошибки не теряют ввод.
  Успех записи в SQLite и ошибка отправки экрана не должны приводить к повторной операции.
- Миграция старой базы повторяема и сохраняет задачи, описания, группы, статусы и
  параметры доставки. Старым задачам не назначать дедлайн/напоминания автоматически.
- Новые таблицы/поля для версий объектов допустимы для защиты от устаревших действий.
- Сохраняй обработку ошибок, маскирование токена, совместимость текущего окружения.
  Новые внешние сервисы и зависимости без необходимости не добавлять.

Проверки:
- Во временных базах и без настоящего Telegram проверить все существующие возможности,
  миграцию/перезапуск, кнопочные диалоги, текст вне формы, фильтры и страницы, дедлайны
  без времени/с временем, полночь/Новый год/часовые пояса, быстрые напоминания, отмену,
  подтверждения, двойной клик, чужие/подделанные/устаревшие кнопки и ошибки сети/SQLite.
- Адаптировать проверки намеренно изменённых диалогов; не убирать прежнее покрытие
  хранения, прав владельца и доставки. Проверить настоящий диспетчер PTB с подменой API.
- Обновить lab1/README.md и сохранить инструкцию ручной проверки новой версии в lab3.
  Результаты автотестов не выдавать за проверку настоящего Telegram/Railway.

Границы работы:
- Не изменять рабочую пользовательскую SQLite и .env в ходе локальной разработки.
- Не пушить и не деплоить автоматически; пользователь делает облачные шаги самостоятельно.
  Перед миграцией облачной базы нужна актуальная приватная резервная копия Volume.
- Не менять старые промпты/отчёты, не создавать отчёт или вымышленные отзывы друзей.
- Общие списки в Telegram-группах, история чата, повторяющиеся напоминания и отдельный
  веб-интерфейс в эту итерацию не входят.

Выполни реализацию после этапа проектирования, проверь её локально и сообщи фактические
результаты, ограничения и действия для самостоятельного повторного деплоя.
