# Промпт лабораторной № 3: подготовка к Railway

Дата: 10.10.2026.
Объём: только пункты 1–2 согласованного плана. Деплой не выполнять.

Подготовь существующего Telegram-бота для последующего запуска на Railway.

Текущий проект:
- Python 3.14, python-telegram-bot с JobQueue, python-dotenv, tzdata.
- Код и тесты находятся в lab1, рабочая база — SQLite.
- Бот использует polling, хранит задачи, группы и параметры напоминаний.
- Настройки: TELEGRAM_BOT_TOKEN, TIMEZONE, DATABASE_PATH.
- Есть проверки владельца, обработка ошибок и скрытие токена в логах.

Пункт 1 — подготовка проекта:
- Проверь имеющиеся тесты, Python и совместимость зависимостей.
- Проверь исключение .env, токена, локального окружения, базы и журналов из Git.
- Создай приватную согласованную резервную копию существующей SQLite через Backup API,
  проверь целостность; не мигрируй и не меняй рабочую базу.
- Не используй настоящий токен в тестах и не показывай его в выводе.
- Документируй, какие проверки выполнены локально, а какие ещё требуют Telegram.

Пункт 2 — подготовка запуска:
- Зафиксируй ветку Python 3.14 в lab1/.python-version.
- Укажи python -u bot.py в lab1/railpack.json, используя актуальную конфигурацию Railpack.
- Исключи секреты, базы, виртуальное окружение и ненужные ресурсы из образа через
  lab1/.dockerignore. Не заменяй существующие зависимости примерами из задания.
- Сохрани настройки для следующего этапа: Root Directory /lab1, TIMEZONE Europe/Moscow,
  DATABASE_PATH /data/tasks.sqlite3, Volume /data, один экземпляр, Serverless выключен.
- Токен позже вводится только в Variables Railway; локальный .env не изменяй.
- Политику перезапуска позже настроить в сервисе с учётом тарифа.
- Если существуют устаревшие способы конфигурации, используй документированный
  современный вариант и объясни выбор в инструкции.
- Добавь локальные тесты конфигурации и приоритета переменных окружения.

Размещение материалов:
- Код, тесты и сборочная конфигурация остаются в lab1.
- Создай lab3 рядом с lab1: план, инструкция подготовки, промпт и история версий.
- Резервные копии храни в lab3/backups, исключённой из Git.
- Не меняй старые промпты и отчёты лабораторных № 1 и № 2.

Границы этапа:
- Не создавать проект в Railway, не подключать репозиторий, не пушить и не деплоить.
- Не выбирать тариф, не создавать Volume и не запускать платные операции.
- Не переводить бота на webhook, не добавлять сервер HTTP, публичный домен или ORM.
- Не создавать отчёт и отзывы; дальнейшие этапы отметить как невыполненные.

Создай конфигурационные файлы и документацию, выполни проверки и кратко опиши результат.
