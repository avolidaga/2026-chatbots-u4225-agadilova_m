## Результаты пункта 2

Railpack читает версию Python из `.python-version`. Значение `3.14` фиксирует ветку,
но не конкретную patch-версию: фактический Python в Linux-сборке проверим по логам
первого деплоя. Переменная `RAILPACK_PYTHON_VERSION`, если задана, имеет приоритет.
[Выбор версии Python](https://railpack.com/languages/python/).

В `railpack.json` задана команда `python -u bot.py`: сообщения выводятся в логи
без буферизации. Установка существующих зависимостей из `requirements.txt` остаётся
автоматической. Кастомные шаги сборки и новые сторонние библиотеки не добавлялись.
[Конфигурация Railpack](https://railpack.com/config/file).

`Procfile` не требуется: актуальная документация рекомендует задавать команду
в `railpack.json` или через `RAILPACK_START_CMD`.
[Настройка команды запуска](https://railpack.com/config/procfile).

Railpack поддерживает `.dockerignore`. Из контекста сборки исключены `.env` и его
варианты, `.venv`, базы и журналы SQLite, логи, резервные копии, кэши, Git-метаданные
и изображения отчётов. Прикладной код, `requirements.txt` и тесты остаются доступными.
[Исключение файлов](https://railpack.com/config/excluding-files).

На этапе подготовки локальный `.env`, зависимости и `bot.py` не менялись.
Последующие изменения кода описаны ниже. Сохраняются polling, SQLite,
группы, поиск, редактирование и напоминания. Веб-сервер и webhook не добавлялись.

## Доработки интерфейса — реализованы локально

По согласованному `v002` в `lab1` добавлены пять улучшений:

- Меню, страницы, карточки и формы на inline-кнопках без обязательного ввода команд/ID.
- Быстрые напоминания с явным подтверждением; «За час до срока» только предлагается.
- Подтверждение удаления задач и групп, защита от двойных/устаревших нажатий.
- Семь фильтров, включая задачи на сегодня и просроченные, в том числе внутри группы.
- Отдельный дедлайн: дата с необязательным временем, независимый от напоминания.

Обычный текст вне формы больше не создаёт задачи. Старые команды сохранены;
`/add Название` остаётся явным быстрым добавлением. Миграция не назначает старым
задачам сроки и сохраняет их данные. Реальная локальная база и `.env` не открывались
для изменения; миграции проверены на временных данных.

Итоговая локальная проверка: **104 теста прошли**, `pip check` успешен на Python 3.14.7.
Новых зависимостей нет. Push, деплой, проверка реального Telegram и сбор отзывов
не выполнялись ассистентом в этой доработке. Предложения не выдаются за фидбэк друзей.
Перед публикацией кода нужна актуальная резервная копия облачного Volume:
[инструкция и сценарии](manual_checks.md).

## Подготовленная конфигурация Railway

Эти значения подготовлены как инструкция. Их применение и фактические значения
в аккаунте Railway нужно проверить пользователю.

| Настройка | Значение |
| --- | --- |
| Source | Наш GitHub-репозиторий, согласованная ветка |
| Root Directory | `/lab1` |
| Builder | Railpack |
| Start Command | `python -u bot.py` — также задана в `railpack.json` |
| Python | Ветка `3.14` из `.python-version` |
| `TELEGRAM_BOT_TOKEN` | Реальный токен вводится только в Variables сервиса |
| `TIMEZONE` | `Europe/Moscow` |
| `DATABASE_PATH` | `/data/tasks.sqlite3` |
| Volume mount path | `/data` |
| Instances / Replicas | Один экземпляр |
| Serverless | Выключен |
| Restart Policy | `On Failure`, до 10 перезапусков для первоначального запуска |
| Public domain / HTTP healthcheck / Cron | Не настраивать для polling-бота |

`DATABASE_PATH` должен указывать внутрь подключённого Volume. Без Volume обычная
файловая система контейнера не обеспечивает постоянное хранение данных между деплоями.
Переменные окружения сервиса имеют приоритет над `.env`; это проверено отдельным тестом.
Локальную базу в образ не включаем: в облаке будет новая база либо согласованный
приватный перенос существующей.

До первого облачного запуска требовалось остановить локальную копию с тем же токеном,
проверить условия тарифа и доступ к Telegram, подключить постоянный диск и настроить
один экземпляр. Облачные действия затем выполнены пользователем; подтверждения
и ограничения проверки описаны ниже и в отчёте.
Не выполнять `setWebhook`: текущий код использует polling.

## Повторная локальная проверка

Из папки `lab1`:

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
```

На Windows используйте `.\.venv\Scripts\python.exe` вместо `.venv/bin/python`.

Новые тесты проверяют версию Python в конфигурации, команду запуска, правила исключений
сборки и приоритет переменных облачного окружения над вымышленным локальным `.env`.
Существующие тесты проверяют команды, ошибки, диспетчер PTB, клавиатуры, SQLite,
миграции и JobQueue с локальной подменой Telegram API.
